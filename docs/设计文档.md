## 1. 定位

把《杀戮尖塔2》的战斗结算改造为「跑团式掷骰判定」：每张牌打出时投掷 **d6 骰池**，按 **四档判定** 决定这张牌是否生效、生效多少，并叠加 **属性分轨** 与 **诅咒抗性 / 诅咒判定** 两条子系统。

- 形态：RitsuLib 内容扩展型 Mod（在结算前插入判定层，不替换原版卡牌）
- 目标游戏版本：Slay the Spire 2 **v0.111.0**（public-beta）
- 全局节奏：输出期望 ≈ 面板值 × **0.98**，另有 ≈6% 概率反噬

## 3. 骰池转化

**骰池期望值 = 卡牌面板值。** 面板值取卡牌的**最终**伤害 / 格挡值（已含力量、敏捷等修正）。

```
n = clamp( round(面板值 / 3.5), 1, 8 )
```

- `3.5` = d6 单骰期望，故 `3.5n ≈ 面板值`
- 骰数上限 **8**，对应面板值 25–28（3 费终结牌）
- **骰数跟数值走，不跟费用走**；费用只是代理指标

## 4. 判定分级

**骰和与阈值分离：骰和只由骰子决定，属性加值与敌人压制都作用在 DC 上。**

```
d         = Σd6                          # 骰和，只由骰子决定
DC        = DC基准(n) − 属性加值 + 压制 Δ  # 属性加值见 §6
大成功阈   = 大成功阈(n)
大失败阈   = 大失败阈(n)
```

三张阈值表**不是解析式**，而是对 n 颗 d6 的**精确组合数分布直接反推**（[DiceCheck.cs](../Scripts/Dice/DiceCheck.cs) 里用 DP 建表，n = 1–8）：

- `DC基准(n)`：使 `P(d ≥ t)` **最接近 84%** 的最小 t
- `大成功阈(n)`：使 `P(d ≥ t)` **最接近 9%** 的最小 t（n = 1 自然得 6 → 「掷 6 大成功」）
- `大失败阈(n)`：使 `P(d < t)` **首次 ≥ 6%** 的最小 t（n = 1 自然得 2 → 「掷 1 大失败」）

| 档位 | 条件 | 目标概率 | 结算效果 |
|---|---|---|---|
| 大成功 | `d ≥ 大成功阈` | ≈ 9%（n = 1 时 17%） | **增幅 ×2.5** |
| 成功 | `d ≥ DC`，且非极值 | ≈ 75% | 原值 ×1.00 ~ ×1.40（见 §5） |
| 失败 | `大失败阈 ≤ d < DC` | ≈ 5–10% | **不生效** |
| 大失败 | `d < 大失败阈` | ≈ 6–10%（n = 1 时 17%） | **不生效 + 反噬**（§5） |

**判定顺序：先判极值、再判 DC。** 极值只由骰和决定，所以属性加值与压制**改不动大成功 / 大失败的概率**，只平移成功 / 失败的边界——高加值时可稳定到「只有掷 1 才会大失败」。若改成先判 DC，高加值会让 DC 跌到大失败阈以下、把大失败档整段吞掉（n = 1 掷 1 就不再是大失败）。

判定**不单独掷骰**——四档就是对原判断的四种处理：**{增幅 / 原值 / 无效 / 反噬}**。能量照常支付。

输出期望 = `2.5×0.09 + 1.2×0.75 + 0×0.10 + 0×0.06 ≈ 1.13`（成功档均值约 ×1.2），另加 ≈ 6% 概率的反噬。

> 旧版曾用正态近似（`DC = μ − 1.0σ`、极值 ±1.5σ）＋「加值计入骰和」，已弃用：小骰池离散尾部太薄导致大失败恒 ≈0–3%，且加值整体右移分布会把小骰池的极值档架空。详见 §9 / 附录 B。

> 大成功系数由 ×2.0 提到 **×2.5**，用于补偿「失败=0、大失败=0」造成的期望塌陷；若不想要补偿，改回 ×2.0（§9 旋钮），代价是全局约 −13%。

### 4.3 边界

- **n = 1（单骰）**：6 个面恰好划满四档 → **掷 1 = 大失败、2–5 = 成功、掷 6 = 大成功**，中间的「失败」档为空。单骰的极值各 16.7%（远高于目标 6% / 9%），这是让最小面板值的牌也保有戏剧性的刻意取舍。
- **多段攻击**（Shiv、Gunk Up 4×3 等）：**整张牌判定一次**，多段共用同一结果，不逐段掷骰。
- **0 费牌失败的代价更高**：0 费牌虽不耗能量，但失败＝白占一个出牌位、白抽一张——属刻意设计。
- **X 费牌**：面板值 = 单点面板 × X（X = 打出前的剩余能量），再走同一套 `n/DC/阈值`；大成功只放大单点值，结算时天然乘 X。

## 5. 牌型效果

**判定结果只有四种处理：增幅 / 原值 / 无效 / 反噬。**

- **成功**：卡牌按面板原值生效，且**随超出 DC 的幅度在 ×1.00 ~ ×1.40 之间浮动**——`倍率 = 1 + 0.4 × (骰和 − DC) / (大成功阈 − DC)`，刚好过线 ×1.00、贴到大成功阈 ×1.40。四档阈值与概率完全不受它影响，纯表现层差异（[RollTier.cs](../Scripts/Dice/RollTier.cs) 的 `EffectMultiplier`）。一张牌上**所有**可数值化效果（伤害、Debuff 层数、格挡、施加层数、抽牌数、获得能量）同步缩放。
- **大成功**：同一张牌上**所有**可数值化效果 **×2.5**。
- **失败**：**整张牌不生效**，能量照付。
- **大失败**：**整张牌不生效**，并触发**反噬**。

### 5.1 反噬表（按牌型）

| 牌型 | 大失败反噬 |
|---|---|
| **攻击 Attack** | 自身受到 `面板值 × 0.5` 伤害（**无视格挡**） |
| **技能 / 防御 Skill** | 自身受到 `面板值 × 0.5` 伤害（**无视格挡**） |
| **能力 Power** | **惩罚判定骰**（见 §5.2） |
| **诅咒 Curse** | 手牌内不判定；被强制打出时转入 §8 诅咒判定 |
| **状态 Status** | 不判定，原样生效 |

> **失败档不反向**：四档中的「失败」= 整张牌不生效；只有「大失败」才触发上表反噬。

### 5.2 能力牌惩罚判定骰（1d6 固定哈希表）

能力牌大失败时**额外掷 1 颗 d6**，按其点数查表施加惩罚（类别与数值都不同）。确定性、可写死，不需要额外 RNG 源。

| d6 | 惩罚类别 | 数值 |
|---|---|---|
| 1 | 失去能量（本回合） | 1 |
| 2 | 自身获得**虚弱**（本回合） | 1 层 |
| 3 | 自身受到伤害（**无视格挡**） | 4 |
| 4 | 自身获得**易伤**（本回合） | 1 层 |
| 5 | 洗 1 张状态牌（Wound 类）入抽牌堆 | 1 张 |
| 6 | 自身获得 **Doom**（或失去等量生命） | 2 |

> 代码里就是一张 `Dictionary<int, (PenaltyKind, int)>`：
> ```csharp
> static readonly Dictionary<int, (PenaltyKind kind, int amount)> PowerFumbleTable = new() {
>     [1] = (PenaltyKind.LoseEnergy, 1),
>     [2] = (PenaltyKind.Weak, 1),
>     [3] = (PenaltyKind.SelfDamageIgnoringBlock, 4),
>     [4] = (PenaltyKind.Vulnerable, 1),
>     [5] = (PenaltyKind.AddStatusCard, 1),
>     [6] = (PenaltyKind.Doom, 2),
> };
> ```
>
> **M1 实现差异**：第 5 项暂以「自身失去力量 −1」（`StrengthDown`）代替「洗 1 张状态牌」，因为造牌需要尚未确认的卡牌实例化 API；确认后再换回。实现见 [Backlash.cs](../Scripts/Content/Backlash.cs)。

### 5.3 细则

- **能力牌**：若该能力没有层数 / 强度数值（纯触发型），则**跳过判定、直接生效**（无"原判断"可增幅）。
- **取整规则**：所有非整数结果**统一向下取整 `floor()`**，最小值 0（`×2.5` 与反噬的 `×0.5` 都会用到）。
- **多段攻击**：先算总面板值定 n 与档位，再整张牌统一处理。

## 6. 属性分轨

**力量与敏捷在判定时提供独立加值，直接**从 DC 里减去**（`DC = DC基准 − 加值 + Δ`），提升成功几率；骰和不变，故大成功 / 大失败的概率完全不受加值影响。**

| 轨道 | 标签 | 作用牌型 | 判定加值 |
|---|---|---|---|
| **力量 Might** | 力量 | 攻击牌 | `clamp(floor(力量/3), 0, 3)` |
| **敏捷 Agility** | 敏捷 | 技能牌 | `clamp(floor(敏捷/3), 0, 3)` |

- 加值上限 **+3**：把「成功及更优」从 ~84% 推到 ~92%（n = 2 时 91.7%、n = 8 时 94.0%），显著但不封顶
- 加值**只平移成功 / 失败的边界，不动极值**：n ≥ 2 且加值 +3 时，只有掷到大失败阈以下才会大失败
- 加值**只作用于对应牌型**，不跨轨（力量不影响技能牌判定）
- **力量 / 敏捷是双重生效的**：一方面抬高面板值 → 抬高 n（数值变大），另一方面抬高判定加值（成功率变高）——这是刻意的，也是力量 / 敏捷流的强度来源
- **意志**不参与 d6 战斗判定，只用于 §8 诅咒判定（独立 d20 系统）
- 能力牌 / 诅咒 / 状态**无属性加值**（能力牌因此方差更大，属高风险高回报）

**难度对冲**：敌方提供 **压制 Pressure Δ**，直接加到 DC 上，避免属性滚雪球：

| 场景 | Δ |
|---|---|
| Act1 普通 | 0 |
| Act2 普通 | +1 |
| Act3 普通 | +2 |
| 精英 | 额外 +1 |
| Boss | 额外 +2 |

`DC最终 = DC基准 + Δ`，净加值 `属性加值 − Δ` 被约束在 **−2 ~ +1**，全局输出期望维持在面板值的 **0.9–1.1** 区间。

## 7. 诅咒抗性 CR

塔2 **没有心脏**（无 Act4 循环 Boss）。幕结构：

| 幕 | 区域 | Boss |
|---|---|---|
| Act1a | Overgrowth | Vantom / Kin Priest / Ceremonial Beast |
| Act1b | Underdocks（分支） | Lagavulin Matriarch / Soul Fysh / Waterfall Giant |
| Act2 | Hive | Knowledge Demon（380 HP）/ Kaiser Crab / The Insatiable |
| Act3 | Glory | Test Subject / Doormaker（~489 HP）/ Queen（400 HP + Torch Head Amalgam 199 HP） |

每幕 3 精英 + 3 Boss，最高血量 ≈ **Doormaker 489 HP**。

CR 是**玩家侧的诅咒抗性**，由牌组规模与遗物数决定：

```
CR = clamp( floor(牌数 / 4 + 遗物数 / 3), 0, 15 )
```

- 「牌数」= 牌组（`Player.Deck`）张数，「遗物数」= `Player.Relics` 数量；上限 **15**
- CR 随流程自然增长，正好覆盖三幕，故**上限压在 Act3 精英 / Boss**
- 实现见 [CurseCheck.cs](../Scripts/Dice/CurseCheck.cs)

| 阶段 | 自然 CR | 参考内容 |
|---|---|---|
| Act1 普通 | 1–4 | Overgrowth / Underdocks |
| Act1 精英 / Act2 普通 | 5–8 | Hive |
| Act2 精英 / Act3 普通 | 9–12 | Glory |
| Act3 精英与 Boss | 13–15（上限） | Doormaker / Queen |

## 8. 诅咒判定

- 使用**独立于战斗的 d20 判定**，**不复用**战斗的 σ 缩放阈值（复用会导致中后期诅咒几乎必然被免疫）
- 诅咒牌在手牌内不判定；被强制打出时掷 d20，**CR 作为玩家侧加值**，`DC = 15 + 敌人压制 Δ`（§6）
- 四档：

| 档位 | 条件 | 结算 |
|---|---|---|
| 大成功 | d20 自然 20 | **免疫 + 转为增益**（力量 / 敏捷各 +1） |
| 成功 | `d20 + CR ≥ DC` | **免疫**（诅咒不生效） |
| 失败 | `d20 + CR < DC` | 诅咒**照常生效** |
| 大失败 | d20 自然 1 | 诅咒**效果翻倍**（数值 ×2） |

> 自然 20 / 自然 1 的大成功 / 大失败带宽各 ≈5%，与 DC 无关；中段的成功 / 失败随 CR 成长而右移（抗性成长）。
> 实现见 [CurseCheck.cs](../Scripts/Dice/CurseCheck.cs) 与 [DiceJudgementListener.cs](../Scripts/Content/DiceJudgementListener.cs)。

| 诅咒大成功增益 | 力量 / 敏捷 各 +1 | 可整体替换 |
| 诅咒大失败翻倍 | ×2 | 诅咒牌数值翻倍 |
| X 费牌 | 面板值 = 单点面板 × X | X = 打出前的剩余能量；见 §4.3 |

## 10. 待定与开放问题

## 11. 游戏内实现

> 以下 API 名均来自本地 `sts2.xml`（游戏内嵌 XML 文档）与 `mods/STS2-RitsuLib/compat/0.111.0/STS2-RitsuLib.Runtime.xml`，**已核实存在**；标注「待反编译确认」的项需用 ILSpy 打开 `sts2.dll` 复核。

### 11.1 时序

```
玩家出牌 → 能量校验 → CardModel.OnPlay(...)          ← 判定层从这里插入
   ├─ 骰池计算 n / DC / 阈值
   ├─ 弹出骰池 UI，播 0.5–1s 掷骰动画（await）
   ├─ 拿到 S → 定档位 → 反噬表 / 惩罚骰
   ├─ 拦截伤害/格挡数值（乘系数 / 置 0 / 反向）
   └─ 播结果提示 → 继续原版结算
```

关键点：**能量校验发生在 `OnPlayWrapper` 之前**，所以判定必须放在 `CardModel.OnPlay(PlayerChoiceContext, CardPlay)`（返回 `Task`）内部、具体命令执行之前。整条管线是 **async/await** 的，可直接 `await` 自定义等待。

```csharp
// CardModel.OnPlay(PlayerChoiceContext, CardPlay) => Task
var roll = await DiceUi.RollAsync(n);        // 弹窗 + 动画 + 返回结果
ApplyTier(roll, cardPlay);                   // 改系数 / 置 0 / 反噬
await DamageCmd.Attack(...).Execute(choiceContext);   // 原版结算照常走
```

### 11.4 数值拦截（M1 最终方案：缩放 DynamicVar）

**结论：不做任何 Harmony 补丁，改为在 `BeforeCardOnPlay` 里直接缩放卡牌的 DynamicVar，在 `AfterCardOnPlay` 里还原。**

`DynamicVar.BaseValue` 有**公开 setter**，且官方注释明确写着：

> The base value of this DynamicVar. … This is the value that should be used when performing calculations that will modify the game's state.

所以它是「卡牌一切可数值化效果」的唯一汇合点 —— 伤害、格挡、debuff 层数、抽牌数、加能量、治疗全部一起 ×2.5，不需要为每种效果单独找拦截点。

- 实现：遍历 `card.DynamicVars`，`BaseValue = floor(BaseValue × 倍率)`，原始值存入快照；`AfterCardOnPlay` 里按快照还原（**必须还原**，否则同一张牌第二次打出会继续叠乘）。倍率来自判定的 `EffectMultiplier`：大成功 ×2.5，成功 ×1.00~×1.40（§5）。
- **只排除结构型变量 `Repeat`**（多段次数，缩放会变成「段数 × 伤害」双重增幅），按**前缀匹配**排除（键名可能带编号后缀，如 `Repeat0`）。`CalculationBase` / `ExtraDamage` 虽是 `CalculatedDamage` / `CalculatedBlock` 的输入，但引擎按「base + extra × 计数」运行时重算，**必须跟着缩放**，否则这类牌的大成功会完全失效。见 [RollRegistry.cs](../Scripts/Dice/RollRegistry.cs) 里的 `DynamicVarScaler.MetaPrefixes`。
- `BaseValue == 0` 的变量跳过（多数卡牌只声明两三张）。

**为什么不用下面这些方案**：

- `IAttackHitHookListener.BeforeAttackHit`：`AttackHitHook` **没有**全局注册方法，只能走「模型能力挂载」，且它只覆盖攻击，格挡 / 层数 / 抽牌都不管。
- `ICardOnPlayHookListener.BeforeCardOnPlay` 拿不到伤害数字 —— 但在 DynamicVar 方案里这**不再是问题**，因为我们改的是卡牌自身的输入值，而不是结算结果。
- Harmony 打在 `Hook.ModifyDamage` / `Hook.ModifyBlock` 上：只能覆盖伤害与格挡，且会与 DynamicVar 方案**叠乘**（2.5 × 2.5 = 6.25），M1 已实测到该风险后弃用。
- 内部顺序供参考：伤害 `EnchantDamageAdditive/Multiplicative → ModifyDamageAdditive → ModifyDamageMultiplicative → ModifyDamageCap`；格挡 `BeforeBlockGained → ModifyBlock → AfterModifyingBlockAmount → AfterBlockGained`。

## 12. 结算计算方式一览（代码实现对账）

> 本节是**代码当前实际行为**的逐项确认（与 §3–§8 的设计一致），所有非整数结果统一 `floor()`、最小值 0。

### 12.1 战斗判定链（d6 骰池）

| # | 环节 | 计算方式 | 代码 |
|---|---|---|---|
| ① | 面板值 base | 取 DynamicVar 中 `Damage` → `Block` → 名以 `Power` 结尾的最大 `BaseValue`；全为 0 → **跳过判定、直接生效** | [CardPanel.cs](../Scripts/Dice/CardPanel.cs) |
| ② | X 费牌 | `base ← base × X`，`X = max(1, 打出前剩余能量)` | [DiceJudgementListener.cs](../Scripts/Content/DiceJudgementListener.cs) |
| ③ | 骰数 n | `n = clamp(round(base / 3.5), 1, 8)` | [DiceCheck.cs](../Scripts/Dice/DiceCheck.cs) |
| ④ | 骰和 d | 掷 n 颗 d6：`d = Σd6` | 同上 |
| ⑤ | 属性加值 a | `a = clamp(floor(属性 / 3), 0, 3)`；力量→攻击牌、敏捷→技能牌，其余 0；**只减 DC，不进骰和** | [CardPanel.cs](../Scripts/Dice/CardPanel.cs) |
| ⑥ | DC | `DC = DC基准(n) − a + Δ`，`DC基准(n)` 由精确分布反推（使 `P(d ≥ t)` 最接近 84%） | [DiceCheck.cs](../Scripts/Dice/DiceCheck.cs) |
| ⑦ | 大成功阈 | `T⁺ = 大成功阈(n)`，反推使 `P(d ≥ t)` 最接近 9%；n = 1 → 6 | 同上 |
| ⑧ | 大失败阈 | `T⁻ = 大失败阈(n)`，反推使 `P(d < t)` 首次 ≥ 6%；n = 1 → 2 | 同上 |
| ⑨ | 比较量 | 只用骰和 `d`（**不含加值**，见 ⑤），故极值档概率与 a / Δ 无关 | [RollTier.cs](../Scripts/Dice/RollTier.cs) |
| ⑩ | 分档 | **先判极值、再判 DC**：`d ≥ T⁺` → 大成功；否则 `d < T⁻` → 大失败；否则 `d ≥ DC` → 成功；否则失败 | [DiceCheck.cs](../Scripts/Dice/DiceCheck.cs) |

### 12.2 四档的结算动作

| # | 档位 | 结算动作 |
|---|---|---|
| ⑪ | 大成功 | 卡牌**所有**数值型 DynamicVar `BaseValue ← floor(×2.5)`；出牌后按快照还原。**仅排除 `Repeat` 前缀**（按前缀匹配，如 `Repeat0`），跳过 0 值变量（[RollRegistry.cs](../Scripts/Dice/RollRegistry.cs)） |
| ⑫ | 成功 | 数值型 DynamicVar `BaseValue ← floor(base × 倍率)`，倍率 = `1 + 0.4 × (d − DC) / (T⁺ − DC)` ∈ [1.00, 1.40]；出牌后同样还原 |
| ⑬ | 失败 | `BeforeCardOnPlay` 返回 `true` → **整张牌不生效**（能量照付，无反噬） |
| ⑭ | 大失败 | 跳过 `OnPlay` + 反噬（⑮ / ⑯） |
| ⑮ | ↳ 攻击 / 技能反噬 | 自身受 `floor(base × 0.5)` 的**无视格挡**伤害（`ValueProp.Unblockable`） |
| ⑯ | ↳ 能力牌反噬 | 额外掷 **1d6** 查表：1 失能 1 / 2 虚弱 1 / 3 自伤 4 / 4 易伤 1 / 5 失力 1\* / 6 Doom 2（[Backlash.cs](../Scripts/Content/Backlash.cs)） |

\* 惩罚骰第 5 项设计为「洗 1 张状态牌入抽牌堆」，M1 暂以「失去 1 点力量」代替（§5.2 / §10-5）。

### 12.3 属性与压制

| # | 环节 | 计算方式 |
|---|---|---|
| ⑰ | 敌人压制 Δ | `Δ = 幕（Act1 0 / Act2 +1 / Act3 +2）＋ 房型（精英 +1 / Boss +2）`；**只加到 DC**（[EnemyPressure.cs](../Scripts/Dice/EnemyPressure.cs)） |

### 12.4 诅咒判定（独立 d20）

| # | 环节 | 计算方式 |
|---|---|---|
| ⑱ | 诅咒抗性 CR | `CR = clamp(floor(牌数 / 4 + 遗物数 / 3), 0, 15)`（[CurseCheck.cs](../Scripts/Dice/CurseCheck.cs)） |
| ⑲ | 诅咒判定 | 掷 d20：**自然 20 → 大成功**（免疫 + 力量 / 敏捷各 +1）；**自然 1 → 大失败**（诅咒数值 ×2、floor 后还原）；其余 `d20 + CR ≥ 15 + Δ` → 成功（免疫），否则失败（照常生效）。DC 也吃 §12-⑰ 的压制 Δ |

### 12.5 恒不判定的牌与 RNG

| # | 规则 |
|---|---|
| ⑳ | 判定 RNG = RitsuLib 的 **run RNG 流** `"TrpgDice"`（`GetModRunRng(player, ModId, "TrpgDice")`），多人两端同序列、逐次消费保持同步 |
| — | **状态牌**：恒不判定、原样生效；**诅咒牌**：在手牌内不判，被强制打出时才走 §12.4 |

### 12.6 闭环校验

- 四档概率、主参数表与输出期望见 **§4 / 附录 B**：大成功 ≈ 9%、成功 ≈ 75%、失败 ≈ 5–10%、大失败 ≈ 6–10%（精确组合数分布反推，非正态近似）。
- 输出期望 = `2.5×0.09 + 1.2×0.75 + 0×0.10 + 0×0.06 ≈ 1.13`；另有 ≈ 6% 概率触发一次反噬（大失败档）。
- **属性加值与敌人压制都只改 DC、不改骰和**，所以大成功 / 大失败的概率恒定，只有成功 / 失败两档随 a − Δ 左右平移。

## 附录 B：数学推导

- d6 骰池：`μ = 3.5n`，`σ = 1.708·√n`（仅用于直觉估计，**不再用于定阈值**）
- **精确组合数分布**：`C(n, s) = [x^s] (x + x² + … + x⁶)^n`，用 DP 建表（`DiceCheck.BuildSumCounts`），`P(d ≥ t) = Σ_{s≥t} C(n, s) / 6^n`
- 阈值 = 对精确分布反解，而非套 σ：
  - `DC基准(n) = argmin_t |P(d ≥ t) − 0.84|`（取最小 t）
  - `大成功阈(n) = argmin_t |P(d ≥ t) − 0.09|`（取最小 t）→ n = 1 得 6
  - `大失败阈(n) = min{ t : P(d < t) ≥ 0.06 }` → n = 1 得 2，n = 2 得 4（8.3%）
- **对称性约束仍在**：d6 和关于 μ 对称，故 `P(d ≥ 大成功阈) ≈ P(d < 大失败阈)`；离散小骰池下两侧无法同时精确命中目标，实际落在 6–10%。（n = 1 例外，各 16.7%。）
- **属性加值的影响**：`DC ← DC基准 − a + Δ`，加值只移动 DC、**不动骰和**，所以极值概率恒定，只有成功 / 失败边界平移。+3 时 n = 2 的成功及更优从 83.3% → 91.7%。
- **输出期望**（×2.5 / 成功均值 ×1.2 / ×0 / ×0）≈ **1.13**；失败与大失败均不产出，大失败额外反噬。

**废弃方案（方向 A′ 正态近似：`DC = μ − 1.0σ`、极值 ±1.5σ、加值计入骰和）**：理论概率 ≈ 9/75/9/6%，但实测不合格——小骰池离散尾部太薄（2d6 双 1 仅 2.8%），大失败恒 ≈0–3%；`n ≤ 1` 硬编码排除极值使面板 ≤5 的牌（实测占 42.9%）大失败恒 0%；加值计入骰和会把整条分布右移，`+3` 时 1–2 骰牌判定被完全架空（成功 100%）。故改为**精确分布反推阈值 + 加值移到 DC + 放开单骰极值**。

**更早初版（方向 A 原式 `DC = round(3.5n−4)`，固定 ±8/−5）**：成功合计 82–100% 且随骰数**反向漂移**，大成功 0→26% 单调暴涨，大失败恒 ≈0–2.4%，不合格。
